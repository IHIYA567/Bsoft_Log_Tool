# Bsoft 日志自动填充工具 (Bsoft_Log_Tool)

🚀 **当前版本：V2.3.1**

## 🚀 工具简介
本工具是专为 Bsoft（创业软件）系统供应商及实施团队开发的日志录入辅助插件。旨在解决在 `primary.bsoft.com.cn:5035` 系统中录入每日工程日志时，表单项繁琐、重复操作多的痛点。

> ⚠️ **V2.2 重要适配**：公司日志页已迁移到 `https://primary.bsoft.com.cn:5035/vueoffice/ProjectLog`。
> 新页面是 Vue3 + Vite 外壳，通过 **无界(wujie)微前端**把原来的 vue-antd-pro 日志页挂进
> `<wujie-app>` 的 **Shadow DOM**。V2.1 只查主文档，穿透不了 shadowRoot，所有点击与状态扫描
> 全部落空，因此面板清一色「⚡ 差异」。V2.2 已修复，并同时兼容旧地址直连。

通过预设逻辑与智能匹配，实现一键秒级完成“出差状态、住宿情况、计划类型、合同范围、角色、工作方式、工作内容类别、任务结果、工时”等十余项表单数据的全自动填充。

---

## ✨ 核心功能
* **🤖 智能表单识别**：基于 Ant Design 组件特征，精准定位单选框（Radio）、复选框（Checkbox）及数字输入框，实现一键精准触达。
* **🧩 微前端穿透（V2.2）**：自动递归收集主文档、所有 open Shadow DOM（wujie-app）与同源 iframe，只在真正含表单的文档根内操作；表单异步挂载时自动等待，并对填充结果做多轮校验与自愈重试。
* **📁 多维度配置映射**：内置完整的日志字典映射，支持对住宿情况、工作计划、合同范围、人员角色、工作方式、任务类别、执行结果等进行个性化预设。
* **⚙️ 动态进入页面自启**：支持自定义 `1s - 10s` 的启动延迟。开启后，每次进入日志页面，工具将在后台自动等待网页 DOM 加载完毕并执行全自动勾选，无需手动干预。
* **📊 集中监控矩阵**：填充完成后自动唤起右侧浮动看板，实时扫描并比对当前页面实际勾选值与配置预期，同步状态（✅ 已同步 / ⚡ 差异 / ⏳ 校验中 / ⏭ 项目无此选项）一目了然；点击后约 120ms 立即弹出，校验结果在面板内就地刷新，3 秒后自动淡出，也可通过底部红色按钮立即关闭。
* **💾 持久化配置管理**：所有配置改动即时生效，并自动保存至浏览器本地存储，下次打开页面或浏览器重启后依然保留个性化预设。

## 🛠️ 安装指南
### 作为原生 Chrome 扩展加载
1.  下载本项目源代码并解压（确保包含 `manifest.json`、`content.js` 等文件）。
2.  打开 Chrome 浏览器，访问 `chrome://extensions/` 页面。
3.  在右上方开启 **“开发者模式”**（Developer mode）。
4.  点击左上角 **“加载已解压的扩展程序”**（Load unpacked），选中含有 `manifest.json` 的文件夹即可完成安装。

## ⚙️ 技术实现
* **语言**：纯原生 JavaScript (ES6+)
* **存储**：利用 `chrome.storage.local` 高效实现多配置项、高隔离性的持久化存储，改动即时生效。
* **UI 注入**：基于原生 CSS `@keyframes` 动画与高性能 DOM 渲染，构建非侵入式的悬浮窗与状态监控面板，不破坏原本页面的样式与布局。
* **兼容性**：完美支持主流 Chromium 内核浏览器（Chrome、Edge、百分浏览器等）；同时兼容新版 `/vueoffice/ProjectLog` 微前端页面与旧版 `/office/#/ProjectLog` 直连页面。

### V2.2 修复清单
* `getDOMRoots()` / `queryAll()`：递归收集 `<wujie-app>` 的 Shadow DOM 与同源 iframe，替换所有 `document.querySelectorAll`。
* `getFormRoots()`：只在含 `.ant-form-item` 的文档根里操作，避免误点 Vue3 外壳的菜单按钮。
* `waitForFormReady()`：子应用异步挂载时轮询等待（最长 20s），页面未就绪时显示等待提示，不再依赖固定秒数硬跑。
* `makeEvent()` / `fireOptionClick()`：事件带 `composed` 以跨 Shadow 边界；优先点击原生 `input`，确保触发 `change` 让 Vue 状态同步。
* `verifyAndRender()`：填充后多轮校验（最多 3 轮），发现差异自动补填一次，消除微前端重渲染延迟造成的误报。
* 监控矩阵新增「🔍 容器」一行，直接显示当前表单在微前端 Shadow DOM 还是主文档，便于以后排查。
* 矩阵最后一行（⏳ 日志工时）下方新增红色「✖ 关闭监控矩阵」按钮，占满一整排；点击即时反馈（文字变「✅ 已关闭」、变灰、缩放），120ms 后淡出关闭面板；未手动关闭时 3 秒自动淡出。
* **修复设置面板单字段联动**：旧实现只点一次、50ms 就释放写权限锁，微前端里事件偶发丢失就永久不生效。现在改下拉/出差/工时会强制刷新容器、点击后严格校验 Vue 渲染的 `checked` 类（不再被原生 `input.checked` 假阳性骗过）、失败自动升级点击策略重试最多 4 次，全程持锁，并在控件上绿闪（成功）/红闪（失败）反馈。
* **项目没有该选项时不再卡红框**：`fieldStatus()` 配合 `findFieldOptions()` 做三态探测（`ok` / `retry` / `unavailable`）。例如项目不提供「合同外」或该 radio 被 disabled 时，预检直接跳过、一次都不点，给黄色提示闪 + 顶部文字说明「当前项目不提供…配置已保留」；监控矩阵显示中性灰色「⏭ 项目无此选项」，不算差异也不触发补填。`flashFieldResult()` 改用 WeakMap 管理定时器并统一把 `boxShadow` 复位为空，修掉连续操作时把上一次红闪当原始样式写回、导致红框永久残留的问题。
* **矩阵弹出提速**：旧逻辑要等全部校验轮跑完（500ms 首轮 + 最多 2×600ms，最慢 1.7s）才创建面板。现在首帧 120ms 即渲染，未完成的项显示「⏳ 校验中」，后续每 400ms 只更新面板内的行（`updateMatrixRows`），不重建 DOM、不重置关闭按钮和 3 秒倒计时；总校验约 0.9s 完成，视觉上零等待。

### 代码清理（无功能变更）
* 删除废弃配置项 `fill_workload`（旧版「是否填工时」开关已移除，代码里从未读取）、只写不读的 `state.checked`、永远走不到的 `executeAction=false` 分支，以及无用的 `'skip'` 别名。
* 把点击、状态扫描、可用性探测里三份复制粘贴的 DOM 遍历合并为 `findFieldOptions()`，`checkItemStatus()` / `probeTargetOption()` 随之删除；`fieldStatus()` 从「扫两遍 DOM」变为扫一遍。
* `hasReadyForm()` 与容器描述共用 `detectFormRoots()`，补齐了原来 wujie 降级 iframe 模式探测不到表单的盲区。
* 移除已废弃且多余的 `document.execCommand('delete')`、工时校验里的 `aria-valuenow` / 父元素文本兜底；读取本地配置改为与默认值合并，避免旧存档缺字段时出现 `undefined`。

### V2.3 可靠性加固
* **并发写权限**：写权限由布尔量改为引用计数（自动填充与设置面板各自持锁，互不覆盖），修复单字段操作 `finish()` 提前释放共享锁、导致自动填充补填点击被 guard 拦截的问题；重复点击「自动填充」会被忽略，锁最终归零。（其中「设置改动排队」已在 V2.3.1 移除，见下）
* **首帧面板不再丢失**：矩阵首帧改为无条件渲染，不再依赖 `auto_run` 或当时的写锁状态。
* **去掉静默兜底**：`是否出差` / `工时` 控件定位失败时，不再默默取页面第一个 checkbox 或第一个数字输入框（可能点错「是否加班」之类字段）。只有候选恰好唯一时才使用；找不到时矩阵显示黄色「⚠️ 未找到控件」，状态检查返回 `null` 与「值不匹配」区分开。
* **一键诊断导出**：设置面板新增「📋 导出诊断日志」。常驻滚动记录容器根数量、字段命中数、三态判定、点击策略、重试次数、锁事件与各轮校验结果；弹窗支持复制到剪贴板与下载 `.txt`。填充不对时把这份文本发出来即可定位，不必再抓前端静态资源。日志只含技术信息，不采集业务数据。

### V2.3.1 并发排队回退（简化）
* 评审后确认「自动填充期间设置改动排队」属于过度设计：触发窗口仅 120ms～920ms，冲突后果最多是矩阵多一行「⚡ 差异」且能自愈；队列却引入 3 个状态与一条定时调度路径，一旦异常未复位会永久卡住。已删除队列状态机（`_singleFieldQueue` / `_singleFieldBusy` / `dequeueSingleField`），设置改动恢复**立即执行**。
* 保留引用计数写锁、防重入标记、首帧无条件渲染。补填轮与设置改动读同一份 `userConfig`，两者最终收敛到用户最新选择，无需串行化。
* 补上异常兜底：自动填充执行体与单字段点击均包 `try/catch`，保证任何异常下 `verifyAndRender` 仍会进入末轮，防重入标记与写锁一定复位。
